安全白皮书

加密设计与安全架构。

本文档详细说明保险库的加密方案、密钥管理、威胁模型与平台安全机制。

加密架构

密钥派生

主密码经 scrypt(N=2¹⁶, r=8, p=1) 派生为 256-bit 主密钥。scrypt 是业界广泛采用的 memory-hard 函数，可有效抵御 ASIC/GPU 暴力破解。

对称加密

使用 AES-256-GCM（Galois/Counter Mode），在加密同时提供完整性认证，防止密文被篡改。每条加密操作使用独立随机 Nonce。

文件格式

布局为 MAGIC(4B) + VERSION(1B) + SALT(16B) + NONCE(12B) + CIPHERTEXT(含 GCM tag)。与桌面端 .pmv 文件格式字节完全对齐，可双向互导。

密钥管理

主密码

主密码仅用于派生密钥，不落盘、不缓存。每次解锁均需重新输入或通过生物识别验证后从 AndroidKeyStore 安全读取。

生物识别

指纹/面部数据由 AndroidKeyStore 用 AES/GCM 包裹主密码持久化存储，密钥材料绑定 TEE/SE 硬件隔离，操作系统也无法提取原始生物特征。

会话安全

解锁后明文主密钥仅存于应用进程内存，锁定时立即清空。Android 最近任务卡片通过 FLAG_SECURE 隐藏内容，防止后台快照泄露。

恢复口令

通过预设安全问题 + 答案派生恢复密钥，不依赖任何第三方。答案经 scrypt 派生后用于解密存储在本地的主密码恢复包。

平台安全

屏幕防护

全局 FLAG_SECURE 禁止截屏、录屏与系统投屏。副作用是将部分设备刷新率限制在 60Hz，应用启动时会主动向系统请求最高刷新率模式。

剪贴板防护

复制密码等敏感字段时标记为 is_sensitive（Android 13+ 系统隐藏预览）。剪贴板内容 60 秒后自动清空，低版本使用 Toast 覆盖提示。

暴力破解冷却

解锁连续失败 5 次后进入指数后退冷却：30s → 60s → 90s → … 每次失败冷却期翻倍，冷却期内拒绝所有解锁尝试。

敏感信息门禁

查看银行卡、身份证、API 密钥等敏感条目的详细字段或图片，以及执行修改主密码、导出等操作前，均需二次输入当前主密码。

自动填充安全

逐次认证

每次填充或保存新凭证均需通过当前保险库的强生物识别或主密码验证。后台不维护明文免验证缓存。

来源验证

按关联应用包名或 HTTPS 主机精确匹配来源。拒绝来自本应用、系统设置/权限管理等敏感来源的填充请求。

安全边界

不使用无障碍服务、悬浮窗、自启动或电池白名单权限。自动填充仅作用于登录类型条目，不影响其他条目类别。

同步安全

传输加密

WebDAV 连接强制 HTTPS，支持 TLS 证书指纹固定（SHA-256）。局域网同步使用 SPAKE2P256 零知识密钥交换建立加密通道。

端到端

同步过程中数据始终处于加密状态（AES-256-GCM），传输的仅为密文。服务端、中间人或云盘提供商均无法解密内容。

完整性校验

同步完成后读回密文并解密校验，确保数据未在传输或存储过程中损坏。逻辑内容一致时跳过不必要的远端重写。

威胁模型

本地攻击者

同一设备上的恶意应用通过 FLAG_SECURE 和应用沙箱隔离被阻止访问保险库数据。主密码或生物识别验证是访问保险库内容的唯一途径。

设备丢失

设备锁屏本身是第一道防线。保险库文件使用 scrypt + AES-256-GCM 加密，无主密码无法解密。暴力破解受冷却机制限制。

离线攻击

攻击者即使获取到保险库 .pmv 文件，也需要破解 scrypt 派生函数后才能尝试 AES 解密。scrypt 的 memory-hard 特性使大规模并行攻击成本极高。
